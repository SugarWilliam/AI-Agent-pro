# 量化幻方矩阵 — 实时数据获取瓶颈与改进方案

**问题**：量化幻方目前无法有效获取足够多的实时信息与实时数据，导致分析与报告质量受限。

**根因**：应用为**纯前端**、无自有后端；实时数据来源仅依赖「网络搜索 + 用户输入」，且多轮对话时默认关闭网络搜索。

**实施状态**：**按本方案已全部实施，维持前端模式、不建后端。** 二、已落地的改进（2.1 量化幻方多轮也执行网络搜索 + 2.2 数据补全请求模板）均已在 `js/events.js`、`js/app.js` 中完成；三、可选进阶方案未实施，仅作后续扩展参考。

---

## 一、当前数据流与瓶颈

| 来源 | 说明 | 局限 |
|------|------|------|
| **网络搜索 (MCP)** | 用户开启「网络搜索」后，首轮会生成搜索词并执行多源搜索、爬取前几条结果注入上下文 | ① **多轮对话时被关闭**（`enableWebSearch && !isMultiTurn`），后续轮无法自动刷新；② 搜索结果多为新闻/百科，**缺乏结构化行情与财报**（如 PE TTM、净利润、可比公司表） |
| **RAG** | 21 个 RAG 以 defaultContent + 用户上传文档为主；externalSources 为**预同步/向量检索**，非每次请求拉取实时 URL | **不提供实时行情与财报**，仅方法论与渠道说明 |
| **用户输入** | 用户可在消息中粘贴股价、PE、公告摘要等 | 依赖用户主动提供，且格式不统一，模型需从自然语言中抽取 |
| **LLM 训练数据** | 模型记忆中的历史数据 | 已通过「禁止占位与模拟」「数据须来自本次检索」等条款**禁止**作为当前数据使用，否则违反数据贞操 |

因此，**在未提供后端或第三方数据 API 的前提下**，实时数据是否充足主要取决于：  
① 网络搜索是否在**需要刷新的轮次**执行；② 用户是否**按结构化方式补充**关键数据。

---

## 二、已落地的改进（本方案）

### 2.1 量化幻方多轮对话也执行网络搜索

- **逻辑**：当当前助手为「量化幻方矩阵」且用户已开启「网络搜索」时，**多轮对话也执行网络搜索**（不再仅首轮）。
- **效果**：用户可在同一对话中说「用最新行情再评估一次」「刷新一下 600183 的估值」等，触发新一轮搜索并注入上下文，提升实时性。
- **实现**：`js/events.js` 中 `enableWebSearch` 条件改为：在 `quant_magic_square` 下不因 `isMultiTurn` 关闭搜索（见代码修改）。
- **注意**：多轮都搜索会增加延迟与调用次数，若需节省可关闭当次对话的「网络搜索」或后续增加「仅首轮搜索」选项。

### 2.2 数据补全请求模板（RAG + 输出规范）

- **逻辑**：在 B/C 级数据状态下，要求模型输出**结构化「数据补全请求」**，便于用户一次性粘贴关键数据（当前价、PE TTM、净利润、一致预期、可比公司等），减少来回澄清。
- **实现**：在 `rag_quant_output_protocols` 的 defaultContent 中增加「数据补全请求模板」示例；输出规范中明确「数据不足时须给出可复制粘贴的补全清单」。
- **效果**：用户按模板从东方财富/巨潮/交易所等抄录后回复，模型即可基于该数据做定量分析，提高单轮信息密度与报告质量。

## 三、可选进阶方案（需额外开发或部署）

| 方案 | 说明 | 成本与约束 |
|------|------|------------|
| **用户侧「关键数据」输入区** | 在输入框旁或弹窗中增加可选字段：股票代码、当前价、PE TTM、最近一期净利润、一致预期增速、可比公司及 PE 等；发送时以结构化文本拼入消息 | 前端开发；无后端；数据仍为用户手动填写或从别处复制 |
| **自建轻量数据接口** | 用户自建 serverless/后端，调用 AkShare 或 Tushare 等，对前端暴露「按代码查行情/财报」接口；前端在量化幻方提问时先请求该接口，将返回 JSON 注入上下文 | 需用户部署与配置（如 Tushare token）；可做成「可选配置项」 |
| **MCP 数据工具** | 开发或接入 MCP 服务，提供 `get_stock_quote(symbol)`、`get_financials(symbol)` 等工具；量化幻方在需要时调用 | 需 MCP 服务运行环境（本地或托管）及 Python/API 密钥等 |
| **爬取指定 URL** | 用户提供「巨潮/交易所某公告链接」，前端或后端抓取该页正文后注入上下文 | 需处理反爬、CORS、合规；可仅作「用户粘贴链接 + 后端/代理抓取」的扩展 |

以上可选方案可在后续版本中按需实现；当前以 **2.1 + 2.2** 为主，在不引入后端的前提下尽量提升实时数据可用性。

---

## 四、使用建议（给用户）

1. **开启「网络搜索」**：在设置或输入区开启网络搜索，并利用「量化幻方多轮也搜索」在追问时刷新最新信息。
2. **首轮尽量带关键数据**：若已知当前价、PE、最新净利润等，在首条消息中直接写出（或按「数据补全请求」模板回复），可显著提高报告质量与结论可信度。
3. **按模板补全**：当报告出现「数据补全行动清单」时，从巨潮、东方财富、交易所等查得数据后，按清单格式一次性回复，便于模型做定量更新。
