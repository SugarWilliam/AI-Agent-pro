## 三、调用顺序与逻辑

### 3.1 组装顺序（buildEnhancedSystemPrompt）

1. 角色与描述  
2. **【当前日期与时间】+【约束重申】**（仅量化幻方，llm.js 注入）  
3. systemPrompt（含禁止、〇～十三、输出规范）  
4. 【规则】  
5. 【技能指引】（29 个 skill 按数组顺序拼接）  
6. 【补充信息：网络搜索结果】（若有）  
7. 【补充信息：工具搜索结果】（若有）  
8. 【知识库参考】queryRAG 合并结果  
9. 【输出格式要求】

**结论**：顺序合理。日期与约束在 systemPrompt 之前注入，确保时效与禁止占位优先；RAG 在技能之后，避免技能被 RAG 长文淹没；规则与技能在 RAG 之前，保证「怎么做」先于「参考什么」。

### 3.2 RAG 调用逻辑

- `queryRAG(userMessage, ragList)` 对**每个** RAG 执行检索/匹配，结果**合并**为一段 `ragContext`。
- RAG 列表顺序**不表示**调用顺序；检索由**用户问题**驱动，相关度低的 RAG 可能返回空，减少噪音。
- **结论**：无顺序依赖，逻辑合理。

### 3.3 技能「调用」逻辑

- 无程序化「条件调用」；29 个技能**全部**按数组顺序拼接进【技能指引】，模型**自行选用**。
- 设计文档建议侧重：核心投资 → 思维 → 研究 → 依赖时序情景 → CN → 决策与行为；当前 skills 数组顺序与该建议基本一致。
- **结论**：顺序合理，由模型按问题选用，无矛盾。

## 四、潜在错误引用与案例/数据风险

### 4.1 风险点

- **RAG / 技能中的示例公司名、代码、数值**：如「长江电力、中国神华、招商银行、中国移动」「沪电股份、深南电路、华正新材」等出现在 CN 框架、核心-卫星、报告输出协议（可比公司示例）等描述中。若模型将此类**方法论示例**误当作**本次分析的标的或可比公司**，会导致错误引用。
- **训练数据中的旧数据**：禁止条款已明确「不得用训练数据中的旧数据冒充当前数据」，但模型仍可能无意中混入记忆中的具体数字（如某年某股 PE），需依赖「注明来源与时间」和「数据须来自本次检索」约束缓解。
- **时间与节点**：报告中的「本报告生成/更新时间」由 llm.js 注入的【当前日期与时间】约束；「等待年报」「复查节点」等由〇·2 时间线动态校准约束。若模型未严格按当前日期倒推，可能出现「年报已发布仍写等待年报」类逻辑错误。

### 4.2 建议（已落实或建议落实）

1. **示例与数据引用防误用**：在 systemPrompt 中显式增加一条——**「RAG 与技能中的公司名、股票代码、具体价格或数值均为方法论示例，不得直接当作本次分析的标的、可比公司或结论数据；具体分析须以本次用户问题与 RAG/网络检索结果为准。」**（见下文 4.3 代码落实）
2. **保持现有约束**：继续强调「关键数据须注明来源与时间」「数据须来自本次检索」；〇·2 时间线动态校准与数据贞操分级响应已能约束大部分误引用。
3. **不在 RAG 中写死具体价格/日期**：当前 RAG 主要为方法论与渠道说明，未发现写死「60元」「70元」等具体价位；若未来新增示例报告片段，应注明「仅为结构示例，数值不可直接引用」。

### 4.3 代码层面落实状态

- ✅ 已在 systemPrompt 〇·2 末尾增加「示例与数据引用」条款：RAG 与技能中的公司名、代码、价格或数值均为方法论示例，不得直接当作本次分析的标的/可比公司/结论数据；具体分析须以本次用户问题与 RAG/网络检索结果为准。
- ✅ 已在 DESIGN_QUANT_MAGIC_SQUARE.md 四、增加 4.6 节「示例与数据引用（防误用）」。
- 技能顺序、RAG 列表、Rules、能力列表与 systemPrompt 的对应关系已一致；重叠均为有意强化，无需删除。
